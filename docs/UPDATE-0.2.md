# 0.2 마우스 탐색 / 기본 보정 — 2026-09-27

사용자 피드백: 타임라인을 마우스로 쉽게 탐색하고 영상마다 밝기/색을 조절하고 싶음.

## 구현

눈금/클립 본문/재생 위치 손잡이 드래그, 가장자리 자동 스크롤, 휠 좌우 이동, 가운데 버튼 패닝, Ctrl+휠 확대 중심 유지.
순서 이동은 ⠿ 손잡이로 분리. 드래그는 pointer capture로 창 안의 트랙 밖에서도 이어지고, 놓거나 창 포커스를 잃으면 종료.
프레임 선택은 스크롤 오프셋과 확대 비율을 함께 반영. 드래그 중에는 브라우저 시크, 놓으면 FFmpeg 정지 프레임으로 확인.

클립별 밝기/대비/채도/따뜻함 -100~100, 숫자/슬라이더/초기화. 한 번의 연속 드래그를 하나의 undo로 묶고 완료 시 자동 저장.
버전 1 JSON은 중립 보정으로 마이그레이션, 버전 2로 저장. 분할 시 보정도 복제하며 동일 미디어를 쓰는 다른 클립은 독립적.

보정 계산은 하나의 RGB affine matrix를 공유한다. 브라우저는 sRGB SVG feColorMatrix, FFmpeg는 RGB geq 후 YUV420으로 변환.
보정 없는 클립은 불필요한 색 필터를 생략한다. API 색 값은 정수/범위를 검증하며 사용자 문자열을 필터에 삽입하지 않는다.

색 비교에서 기존 정규화 사본의 색공간 미표기로 Chromium/FFmpeg의 YUV→RGB 해석이 달랐고, PNG에 제한 범위 정보가 남아 어둡게 보이는 문제를 발견했다.
정규화 사본을 BT.709/limited로 변환·태그하고 캐시 키를 v2로 변경했다. 정지 PNG는 RGB full range/sRGB로 태그한다.
색공간 정보가 없는 원본은 긴 변 1024px 이하 BT.601, 그보다 큰 입력 BT.709로 해석하고 UI에 가정을 표시한다. 카메라별 색 재현을 모두 검증한 것은 아니다.

현재 보정은 정규화된 프레임 전체에 적용하므로 포함된 검은 여백도 밝기/따뜻함에 영향을 받는다.
CPU geq 보정은 출력 처리량을 늘리며 장시간 실촬영본의 출력 성능은 별도 측정 필요. HDR/고급 색보정 범위는 그대로 제외.

참고: [FFmpeg geq](https://ffmpeg.org/ffmpeg-filters.html#geq), [SVG 색 행렬](https://www.w3.org/TR/filter-effects-1/#feColorMatrixElement).
