# 구조와 공통 규칙

## 코드 경계

- `src/shared/project.ts`: 버전 8 프로젝트 스키마(버전 1–7 마이그레이션), 프레임 연산, 분할/트림/리플/순서/히스토리. UI와 main이 함께 검증.
- `src/shared/narration.ts`: 녹음 메타데이터/구간, 겹친 음성 트랙 배치, 프레임과 오디오 샘플 매핑.
- `src/components/NarrationPanel.tsx`: 마이크 선택·레벨 표시, MediaRecorder 녹음과 저장 재시도, 음성 편집. `NarrationPlayback.tsx`: 타임라인 위치를 따르는 음성 재생.
- `electron/narration.ts`: 녹음 WebM을 영구 WAV로 정규화, 제한된 자산 등록과 SHA256 검증.
- `src/shared/canvas.ts`: 허용 비율/해상도, fit/fill/배경, 크롭/배치 사각형 계산, Chromium CSS와 FFmpeg 필터 공통 매핑.
- `src/shared/color.ts`: 밝기/대비/채도/따뜻함과 공통 RGB 행렬, SVG 및 FFmpeg 필터 생성.
- `src/components/Timeline.tsx`: pointer capture, 프레임 변환, rAF 드래그, 가장자리 자동 스크롤, 휠/가운데 버튼 이동, 확대 중심 유지. 본문/⠿ 드래그는 클립 순서 변경, 양끝은 트리밍, 눈금/재생선은 탐색.
- `src/shared/timeline.ts`: 화면 좌표와 프레임 변환, 원본 범위에 맞춘 트림, 각 클립 중간점을 기준으로 한 이동 삽입 위치 계산.
- `src/App.tsx`: 편집 화면과 편집 기록. `src/usePreviewPlayback.ts`: 영상 재생·클립 전환과 녹음 시계 동기화. renderer는 Node/일반 파일 시스템/셸 API를 받지 않음.
- `electron/preload.ts`: 기능별 메서드만 노출. 임의 IPC 채널이나 명령 실행은 노출하지 않음.
- `electron/main.ts`: 파일 선택, 프로젝트 저장, 복구, 작업 직렬화, 승인된 미디어 URL, sender 검증.
- `electron/media.ts`: ffprobe 검사, 정규화, 정확한 컷 렌더, 정지 이미지 추출, 출력 검증.
- `electron/process.ts`: shell:false + 인자 배열, stderr 수집, 제한된 stdout, 실행한 프로세스만 취소.
- `electron/storage.ts`: JSON 스키마 검증, 임시 파일 + fsync + rename, 직전 파일 `.bak`.

FFmpeg/ffprobe는 별도 프로세스입니다. 메인 화면에서 디코딩/인코딩 연산을 수행하지 않습니다.
긴 가져오기/출력은 동시에 하나만 실행하고 AbortController로 해당 자식 프로세스를 종료합니다.
OS 전체 FFmpeg 프로세스 이름을 검색하거나 일괄 종료하지 않습니다.

## 내보내기 최적화와 저장

각 입력은 잘린 시작점의 정수 초까지 입력 탐색(`-ss`) 후 남은 0–29프레임/48kHz 샘플만 잘라냅니다. 소수점 탐색 반올림으로 첫 프레임이 빠지는 문제를 피합니다. 입력 디코더는 2스레드, 합성·인코더는 사용 가능한 CPU 수에 맞춰 최대 8스레드를 사용하며 기존 H.264 veryfast/CRF 20 설정과 해상도는 유지합니다.

색 보정의 공통 RGB 행렬은 지원 범위에서 `colorchannelmixer`로 계산합니다. 불투명 alpha가 밝기·따뜻함의 상수항을 공급하고 최종 합에서 클리핑합니다. 변환 전후 `gbrp`를 명시해 기존 색 경계 보간을 유지합니다. 계수가 ±2를 넘는 극단적인 대비·채도 조합은 기존 `geq` 계산을 사용합니다. 두 경로는 정수 반올림 때문에 작은 픽셀 차이가 있으며 별도 색상 패턴 검사로 확인합니다.

`TaskProgressDialog`는 자막 준비/영상 생성/확인·저장의 현재 단계와 실제 출력 프레임 수를 표시합니다. 파일 확인·저장은 예상 퍼센트를 만들지 않고 처리 중으로 표시합니다. 전체 작업 경과 시간은 별도 컴포넌트 안에서 갱신합니다.

Windows 저장 창의 [기본 덮어쓰기 확인](https://github.com/electron/electron/blob/main/shell/browser/ui/file_dialog_win.cc)을 사용합니다. `export-destination.ts`는 승인한 대상의 파일 식별자·크기·수정 시간을 기억하고, 같은 폴더에서 임시 MP4를 완성·검증한 뒤 재확인하여 원자적으로 교체합니다. 새 파일은 덮어쓰기를 허용하지 않는 하드 링크로 게시하고, 지원하지 않는 볼륨에서는 exclusive 복사를 사용합니다. 저장 도중 파일이 바뀌면 다시 선택하도록 안내합니다. 원본·캐시 대상은 승인 여부와 무관하게 차단하며, 교체 완료 이후의 취소는 완성 파일을 삭제하지 않습니다.

## 편집용 기기 보기

`viewer.ts`는 제조사 화면 해상도와 편집용 유튜브 가이드 여백을 분리해 관리합니다. `viewerGeometry`가 기기 뷰포트 내부의 프로젝트 캔버스 위치·동일 축척을 계산하고, `projectToViewer`가 자막 바운딩 박스를 같은 좌표계로 옮깁니다. contain은 여백, cover는 잘림을 유지합니다. 실제 비디오·자막·도형은 기존 프로젝트 캔버스 안에 그대로 두어 포인터 이동과 FFmpeg 정지 화면 좌표가 일치합니다.

`PreviewCanvas`의 가이드는 캔버스 외부에 있으며 pointer-events를 받지 않습니다. `CaptionOverlay`는 기존 비트맵 크기에 `captionTransform`의 현재 프레임 이동·중심 확대를 적용해 겹침을 검사하고, 변경된 경고만 보고합니다. 투명한 애니메이션 프레임과 표시 시간이 끝난 자막은 경고에서 제외합니다. 별도의 영상 디코딩·FFmpeg 요청은 발생하지 않습니다.

기기·사용자 지정 해상도·여백은 검증된 `vlog-viewer-v1` 로컬 설정이며 프로젝트 v8 / IPC / 내보내기 데이터에 포함하지 않습니다. 레이아웃은 `vlog-layout-v2`에 저장하고 패널은 필요할 때만 공간을 차지합니다. 작은 화면과 큰 배율에서는 도구를 가로로 스크롤하고 타임라인의 최소 높이를 줄입니다.

상하분할형/좌우 분할형 선택, 미리보기 좌우 위치, 폭 비율, 분할형 타임라인 높이는 `vlog-workspace-v1`에 별도로 저장합니다. 이전 설정이 없는 PC는 상하분할형으로 시작하며 `shared/editor-layout.ts`가 저장값을 검증합니다. `workspace-layout.css`의 grid 배치와 `display: contents`로 동일한 컴포넌트를 재배치하므로 전환 중 video/audio DOM, 상세 편집 상태, 선택과 타임라인 스크롤을 유지합니다. 분할형의 보관함/상세 설정은 빠른 편집과 같은 도구 영역을 사용하고, 패널을 닫으면 빠른 편집으로 돌아옵니다. 녹음이나 드래그 편집 중에는 배치 전환을 잠급니다. `npm run test:workspace`는 전환·재생·부분 서식·묶음 저장·배율·설정 복원을 검증합니다.

검증은 `npm test`의 좌표·가림·움직임·설정 복구 검사와 `npm run test:viewer`의 실제 Electron 편집/120가지 좌표 조합/사용자 기기 저장/확대 배율/가이드 유무에 따른 MP4 디코딩 프레임 동일성 비교로 구성합니다.

## 프레임과 소스 시간

프로젝트는 6개 비율 중 선택하며 새 작업은 1080×1920(9:16)입니다. 30fps, SDR은 고정합니다. 기존 1920×1080 프로젝트는 해당 비율을 유지합니다. 클립 구간은 **[inFrame, outFrame)** 정수 프레임입니다.
클립 길이 = outFrame − inFrame. 타임라인 시작 = 앞선 클립 길이의 합.
타임라인 f가 해당 클립에 속하면 sourceFrame = inFrame + f − timelineStart.
30fps 편집용 사본의 시간(초) = sourceFrame / 30. 오디오 48kHz에서는 프로젝트 프레임당 정확히 1600 샘플입니다.
영상은 trim start_frame/end_frame, 오디오는 atrim start_sample/end_sample을 동일 구간으로 자릅니다.

원본 time_base, start_time, 평균 fps, 회전, 해상도는 원본 메타데이터로 별도 보관합니다.
원본 프레임 번호를 프로젝트 프레임 번호로 간주하지 않습니다.
가져올 때 FFmpeg 기본 회전 보정, 영상 PTS 시작 정렬, fps=30, SAR 보정, 긴 변 1920px로 정규화합니다. 편집용 사본에 여백을 굽지 않으며 실제 displayWidth/displayHeight를 미디어에 기록합니다.
예상 원본 시각은 정규화 프레임/30 + 원본 시작 PTS이며, 실제 VFR 프레임 선택은 FFmpeg fps 필터가 원본 PTS에 따라 결정합니다.
회전/VFR 실촬영본의 시간/좌표 매핑 검증은 아직 완료되지 않았습니다. 얼굴 좌표 계층은 4단계 전에 추가하고 자동 테스트합니다.

현재 편집용 사본은 원본 비율/긴 변 1920px의 H.264 CRF18/AAC 192k, 최종 출력은 CRF20/AAC 192k입니다. 캐시 키 v3는 이전 16:9 여백 사본과 분리합니다.
출력에서 동일 사본을 재사용하여 디코더별 회전/프레임 선택 차이를 줄이지만 두 번 인코딩되는 품질 비용이 있습니다.
추후 원본 렌더/저해상도 프록시를 분리할 때 이 시간/좌표 매핑 계약을 유지합니다.

## 미리보기와 출력

재생: `usePreviewPlayback.ts`가 HTMLVideoElement에 편집용 사본을 제공합니다. 일반 미리보기는 영상·오디오의 `currentTime`을 기준으로 타임라인을 갱신합니다. 디코딩/재생 준비가 지연될 때 타임라인을 먼저 전진시키거나 120ms 오차마다 강제 탐색하지 않습니다. 클립 경계 또는 사용자 탐색 때만 위치를 바꾸고, 이어지는 같은 소스 구간과 일시 정지 후 재생은 불필요한 탐색을 피합니다. 영상의 waiting/seeking/pause 동안 별도 녹음 재생도 대기합니다. 마이크 녹음 중에는 단조 증가 시계(performance.now)를 유지해 영상 로딩과 무관하게 녹음 시간을 보존하며 작은 영상 오차는 속도 ±5% 안에서 보정합니다. 0.5초를 넘는 큰 오차의 탐색 보정은 최소 1초 간격으로 제한합니다.
재생 시작은 대상 미디어의 metadata → 원본 시작 프레임 탐색 → seeked/loadeddata 확인 → play 순서입니다. 준비가 끝나기 전에는 일반 재생의 타임라인 갱신을 차단합니다. play 도중 원점으로 돌아간 경우 잘라낸 앞 구간을 재생하며 재생선을 0에 고정하지 않고 시작점 준비를 다시 수행합니다. 이 복구는 최대 세 번으로 제한하며, 연속 재생 중 주기적인 강제 탐색은 하지 않습니다. 트림 시작/끝과 장면의 타임라인 시작 위치도 재생 효과의 의존성에 포함해 같은 클립 ID의 구간 변경에 이전 계산이 남지 않게 합니다.

하드 컷을 재생할 때 미디어 전환/시크 지연이 생길 수 있습니다. 이 경로를 프레임 정확한 재생이라고 표시하지 않습니다.
정지/한 프레임 이동: FFmpeg가 sourceFrame/30 시점의 프레임을 추출합니다. 느린 응답은 오래된 선택에 덮어쓰지 않도록 폐기합니다.
연속 드래그 중에는 브라우저 시크로 빠르게 표시하고 놓으면 정지 프레임을 추출합니다. 새 정지 요청이 들어오면 이전 FFmpeg 정지 요청을 취소하므로 프로세스가 누적되지 않습니다.
정지 미리보기는 선택한 출력 해상도의 절반(9:16은 540×960)으로 만듭니다. 테스트는 같은 크기로 줄인 출력 프레임과 픽셀을 비교합니다.
영상 보정 후 공통 사각형으로 crop/scale/pad합니다. contain은 전체 원본을 유지하고 cover는 목표 비율의 원본 사각형을 먼저 자릅니다. 크롭 위치는 남는 범위의 0–100%이며 YUV420용 짝수 픽셀로 맞춥니다. 여백은 보정과 분리한 단색 배경입니다.
클립별 inherit/contain/cover 및 x/y를 저장합니다. 프로젝트 fit 변경은 inherit 클립에 적용하고, 비율/여백 색은 프로젝트 전체에 적용합니다.
출력: 정규화 사본의 각 영상/오디오 구간을 필터에서 연결하고 CPU 인코딩합니다. 출력 codec/해상도/프레임 수를 검증한 뒤에만 완성 파일로 복사합니다.
실패/취소 임시 파일은 제거하며 기존 파일에는 COPYFILE_EXCL로 덮어쓰기를 금지합니다.

## 사용자 작업과 캐시

Electron userData(`%APPDATA%/VlogTool` 기본값):

- `work/recovery.vlog.json`와 `.bak`: 사용자 작업. 캐시 정리 대상이 아님.
- `recordings/`: 사용자 녹음 원본 WAV. 캐시 정리 대상이 아니며 삭제/Undo 시 파일을 자동 제거하지 않음.
- `cache/normalized/`: 재생성 가능한 정규화 사본. 현재 자동 정리 기능 없음.
- `logs/last-error.log`: 최근 처리 오류. 경로가 포함될 수 있으며 로컬에만 저장.

사용자가 고른 `.vlog.json`은 별도 저장합니다. 저장은 순서대로 처리하고 파일 교체 전에 임시 파일을 동기화합니다.
원본 fingerprint는 정규 경로/크기/mtime의 SHA256입니다. 내용 전체 해시는 아니므로 엄밀한 변조 검증을 의미하지 않습니다.
검증 스크립트에서는 내용 전체 SHA256으로 원본 불변을 확인합니다.
원본 누락/변경 상태는 알리고 내보내기를 제한합니다. 녹음은 프로젝트 명시 저장 시 옆 `.vlog.json.assets` 폴더에 복사하고 상대 경로로 기록합니다. 열 때 프로젝트 폴더 기준 절대 경로로 해석하고 SHA256을 확인합니다. 파일 재연결 UI는 아직 미구현입니다.

## 로컬 접근 경계

contextIsolation=true, nodeIntegration=false, sandbox=true, webSecurity=true.
로컬 `vlog://editor` 앱 리소스와 이미 가져온 미디어 ID만 요청할 수 있습니다. CSP로 원격 스크립트/콘텐츠를 차단합니다.
IPC는 현재 창의 mainFrame와 정확한 앱 URL을 확인하고 JSON/ID/범위를 검증합니다.
새 창/이동/webview, HTTP/HTTPS/WS/WSS 네트워크 요청을 차단합니다. 사용자가 마이크 확인/녹음을 시작한 동안 편집창 mainFrame의 오디오 권한만 허용합니다. 요청/검사 핸들러 모두를 적용하며 카메라와 다른 창의 장치 권한은 거부합니다.
등록된 녹음 ID는 `vlog://editor/narration/<id>`로 제공하며 임의 파일 경로를 URL로 노출하지 않습니다. 녹음 IPC는 최대 64MiB와 30분 길이를 검증하고 별도 UUID 파일을 사용합니다. 원본 WebM과 미완성 WAV는 성공/실패 후 정리합니다.
테스트 전용 `VLOGTOOL_TEST_DATA` 환경 변수는 테스트의 userData를 개발 작업과 분리합니다. UI로 설정할 수 없습니다.

## 자막 / 0.7

자막 스키마와 프레임 연산은 `src/shared/captions.ts`, 공통 Canvas 렌더러는 `caption-renderer.ts`, 숨김 렌더 창과 출력용 단일 PNG 시퀀스는 `electron/captions.ts`에서 관리합니다. 동일 글자 PNG와 프레임별 움직임 계산을 실제 미리보기와 FFmpeg 출력에 사용합니다. 명시적인 zOrder로 합성하고, 시간 겹침은 허용합니다. 영상 보정·맞춤 후 합성하므로 자막 색은 영상 색 보정의 영향을 받지 않습니다.

일반/강조는 클립과 원본 프레임 구간에 연결됩니다. 전체 제목은 clipId=null과 0/0 구간 표식으로 저장하고 현재 타임라인 전체에 표시합니다. 종류별 공통 스타일과 변경한 필드만의 overrides를 분리합니다. UI 배치는 로컬 설정이며 프로젝트 Undo에 포함하지 않습니다.

일반/강조 자막은 재생 위치에서 시작합니다. `CaptionTiming.tsx`는 클립 안에 보이는 구간을 장면 기준 초로 표시하며, 저장은 원본 정수 프레임을 사용합니다. `CaptionLane.tsx`의 구간 이동은 양끝에 같은 델타를 적용해 길이를 유지합니다. 겹침에 따른 행 재배치로 DOM 순서가 바뀌어도 드래그가 취소되지 않도록 포인터 캡처는 고정된 트랙 요소에 둡니다. 단순 클릭, Esc, 원점으로 돌아온 드래그는 숨겨진 원본 구간과 실행 기록을 보존합니다.

렌더 창은 앱과 같은 로컬 프로토콜·글꼴을 이용하지만 일반 편집 IPC를 호출할 권한은 없습니다. Bitmap/scene 요청은 메인에서 검증한 객체를 전달합니다. 자막 텍스트는 Canvas의 텍스트로만 처리합니다. 텍스트·스타일별 PNG 캐시는 64개로 제한하고, 위치와 움직임 변경은 글자 이미지 재생성 없이 합성 좌표/투명도/크기만 바꿉니다. 정적 구간은 합성 이미지를 재사용하고 움직이는 구간만 프레임별 출력합니다. 합성 장면 조회 캐시는 256개입니다. 출력용 자료는 작업별 UUID 하위 폴더에서 생성·정리합니다.

자세한 계약과 검증은 [UPDATE-0.7.md](UPDATE-0.7.md)를 참조합니다.

## 여러 제목과 글 그룹

프로젝트 형식 7은 여러 전체 제목을 허용하며 기존 형식 1~6을 변환합니다. 전체 제목은 각각 별도 ID, 스타일과 겹침 순서를 유지합니다. 글 보관함 형식 2는 기존 단일 스타일·즐겨찾기에 `groups`를 더합니다. 그룹에는 최대 50개 글의 종류·문구·완전한 스타일·클립 내 상대 구간을 저장하며, 그룹을 적용할 때 새 ID로 복사하고 하나의 편집 기록을 만듭니다. 제목은 전체 영상에, 일반/강조 자막은 선택한 클립에 맞춰 배치합니다.

## 부분 서식과 도형 / 형식 8

최신 프로젝트는 형식 8입니다. 자막 `runs`는 UTF-16 선택 범위와 글꼴·크기·굵기·색의 개별 변경값을 저장합니다. `rich-text.ts`는 범위 병합·선택 초기화와 입력/붙여넣기/IME 수정에 따른 구간 이동을 처리하며, 선택 서식은 그래핌 경계를 보존합니다. 혼합 글꼴의 측정·줄바꿈·행별 기준선은 `rich-caption-renderer.ts`에서 수행합니다. 부분 서식이 없는 기존 자막은 기존 렌더 경로를 유지합니다.

`CaptionStyle.gradient`는 두 색과 CSS 기준 각도를 보관합니다. `decoration.ts`는 그라데이션 벡터, 독립 도형 스키마·표시 구간·겹침 순서·도형 좌표를 공유합니다. 도형은 클립의 원본 프레임 구간을 따르며, 영상 분할/삭제 시 함께 분할/삭제됩니다. 미리보기는 SVG, 출력은 Canvas 도형이며 같은 좌표·둥글기·테두리 규칙을 사용합니다. 출력 합성 순서는 뒤쪽 도형 → 자막 → 앞쪽 도형입니다. 도형만 있는 프로젝트도 자막 합성 엔진을 통해 출력합니다.

글 보관함 형식 3은 그룹 항목에 부분 서식을 보존합니다. 이전 프로젝트에는 빈 `runs`/`decorations`, 이전 스타일에는 단색 배경 기본값을 채우고, 보관함 형식 1·2와 이전 배열 형태도 변환합니다. 나눔손글씨 펜 TTF와 OFL 고지를 앱 글꼴 자산에 포함합니다.

단일 스타일과 그룹은 앱의 `useCaptionLibrary`에서 같은 상태와 저장 잠금을 공유합니다. 한쪽 저장이 다른 쪽 내용을 지우지 않도록 전체 보관함을 직렬 저장합니다. 숫자 입력은 `NumericInput`에서 작성 중인 문자열을 분리해 보관하고, Enter/blur 시에만 숫자 검증·범위 보정·편집 기록을 적용합니다. 빈 입력과 Esc는 기존 값으로 복원합니다.

## 제목·꾸미기 묶음과 기본 자막

글 보관함 형식 4는 그룹의 `decorations`에 도형 모양·좌표·색·반경·테두리·글 앞뒤 순서·클립 기준 시간 또는 전체 영상 여부를 함께 저장하고, `defaultGroupId`로 기본 묶음을 참조합니다. 형식 1~3과 이전 배열 보관함은 빈 도형/기본 지정 없음으로 변환하며 기존 문구·부분 서식·스타일·즐겨찾기를 보존합니다. 프로젝트 형식은 8을 유지합니다.

일반 그룹 불러오기는 원래 글 종류와 표시 구간을 복원합니다. 기본 자막 추가는 모든 글을 일반 자막으로 변환하고 모든 구성요소를 현재 소스 프레임부터 장면 끝까지 배치합니다. 새 ID와 독립 복사본을 만들며, 글 2000개/도형 500개 제한을 함께 확인한 후 하나의 편집으로 적용합니다. 템플릿의 배치를 유지하므로 자동 글 위치 보정은 거치지 않습니다. 선택 글과 도형을 덮어써도 이미 적용된 프로젝트 구성은 바뀌지 않습니다. 기본 묶음 삭제는 같은 보관함 저장에서 기본 참조도 해제합니다.

그라데이션의 선택 필드 `mode`는 `soft` 또는 `hard`이며, 필드가 없는 이전 데이터는 소프트로 처리합니다. `gradientStops`를 CSS 견본과 Canvas 배경에서 공유하여 하드 모드의 50% 중복 색상 지점과 각도가 미리보기/출력에서 일치합니다. 프로젝트·보관함 형식 번호는 그대로 유지하며 저장된 스타일과 묶음에도 선택이 보존됩니다.

## 자막 복사와 시간 자동 배치

자막 클립보드는 App의 세션 상태로 문구·runs·확정된 유효 스타일·원본 구간과 표시 길이를 독립 복사합니다. Windows 클립보드와 구분되며 일반 입력칸의 Ctrl+C/V 이벤트는 가로채지 않습니다. 프로젝트 전환 시 유지되고 앱 종료 시 비워집니다. 복제 옵션은 `vlog-caption-copy-v1`에 저장하며 기본값은 꺼짐입니다.

`pasteCaption`은 새 ID로 붙여넣고 `duplicateCaption`도 같은 경로를 사용합니다. 자동 배치는 같은 클립의 원본 표시 끝 이후, 일반·강조 자막의 합쳐진 점유 구간을 건너뛰어 표시 길이를 모두 수용하는 첫 빈 구간을 찾습니다. 전체 제목은 빈 구간 판정에서 제외합니다. 공간 부족/옵션 꺼짐은 원래 시간과 숨겨진 원본 가장자리를 보존하며 기존 위치 분산을 적용합니다. 다른 클립이나 프로젝트는 대상 재생 위치와 클립 끝에 맞춥니다. 붙여넣기는 기존 비트맵 준비 및 배치 경로를 통해 한 번의 실행 취소로 처리됩니다. 자막 타임라인 선택 시 포커스를 이동해 이전 숫자·문구 입력칸이 단축키를 가로채지 않게 합니다.
